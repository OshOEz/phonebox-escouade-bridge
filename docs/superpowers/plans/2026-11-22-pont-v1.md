# Pont v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un process Node qui montre les agents d'Escouade (et leurs sous-agents) dans un widget PhoneBox et fait passer les permissions par la carte d'approbation native de PhoneBox.

**Architecture:** Le pont sonde le serveur MCP local d'Escouade (JSON-RPC `tools/call` en HTTP), construit un instantané compact et le pousse à PhoneBox (`POST /api/push/escouade`). Un widget Custom HTML l'affiche (maquette D). Chaque permission nouvelle part à la route bloquante `/api/hooks/claude/permission` de PhoneBox, et la décision revient à Escouade par `answer_permission`.

**Tech Stack:** Node ≥ 24 (TypeScript exécuté tel quel, `node:test`, `node:http` pour les bouchons), `fetch`, aucune dépendance npm. Widget : HTML/CSS/JS vanilla.

**Spec:** `docs/superpowers/specs/2026-11-22-pont-v1-design.md` (et l'étude `docs/etude.md`)

## Global Constraints

- Node ≥ 24, `"type": "module"`, imports avec l'extension `.ts`, aucune dépendance (ni dev, ni prod).
- Tout en boucle locale : Escouade `http://127.0.0.1:<47000-47999>/mcp`, PhoneBox `http://127.0.0.1:8765` (`PHONEBOX_URL`).
- Requête MCP : `POST`, `Content-Type: application/json`, `Accept: application/json, text/event-stream`, `Authorization: Bearer <jeton>`, `MCP-Protocol-Version: 2025-11-25`, corps `{"jsonrpc":"2.0","id":n,"method":"tools/call","params":{"name","arguments"}}` (pas d'`initialize` nécessaire).
- Le jeton n'apparaît dans aucun log ni message d'erreur.
- Push : clé `escouade`, corps JSON (`Content-Type: application/json`), 64 Ko au plus ; viser < 60 000 caractères.
- Textes visibles en français, avec accents.
- Couleurs du widget (style.css de PhoneBox) : fond `#06080b`, carte `rgba(255,255,255,.045)`, trait `rgba(255,255,255,.08)`, texte `#eef2f6`, gris `#8a94a3`, gris sombre `#5b6472`, accent `#2dd4bf`, vert `#22c55e`, ambre `#f59e0b`, rouge `#ef4444`, police Roboto / Roboto Mono.

## Review Focus

- Escouade fermé ou serveur MCP coupé : le pont ne plante pas, le widget affiche « Escouade ne répond pas » (Task 5, test `offlineSnapshot`).
- Texte d'agent contenant du HTML (`<img onerror>`) : affiché tel quel, jamais interprété ; le widget n'utilise que `textContent` (Task 5, vérif manuelle + grep `innerHTML` interdit hors gabarits statiques).
- Demande répondue dans Escouade pendant que la carte est sur le téléphone : l'appel est annulé et aucune réponse n'est renvoyée (Task 4, test `abortsVanished`).
- 30 agents bavards : l'instantané reste sous 60 000 caractères (Task 2, test `staysUnderPushLimit`).
- PhoneBox renvoie un corps vide (téléphone absent, délai) : rien n'est envoyé à Escouade et la demande n'est pas renvoyée en boucle (Task 4, test `emptyBodyLeavesItAndNeverResends`).

### Task 2: L'instantané pour le widget

**Files:**
- Create: `src/snapshot.ts`, `test/snapshot.test.ts`, `test/fixtures/escouade.ts`

**Interfaces:**
- Consumes: les formes de réponse de `list_agents`, `list_background_work`, `get_agent_summary`, `get_usage` (docs/PROTOCOL.md d'Escouade, recopiées dans `test/fixtures/escouade.ts` comme types `Agent`, `BackgroundWork`, `AgentSummary`, `Usage` — seuls les champs utilisés).
- Produces:
  - `type Status = "waiting" | "running" | "idle" | "error" | "done"`
  - `type SubView = { id: string; desc: string; status: Status; doing: string }`
  - `type AgentView = { id: string; name: string; project: string; status: Status; label: string; color: string; line: string; last: string; model: string; engine: string; ticket: string | null; cost: string; bg: number; subs: SubView[]; subsRunning: number; subsDone: number }`
  - `type Snapshot = { v: 1; at: number; offline: false; totals: { active: number; waiting: number; done: number; cost: string }; quotas: { engine: string; win: string; pct: number; reset: string }[]; costs: { name: string; cost: string; share: number }[]; agents: AgentView[] } | { v: 1; at: number; offline: true; message: string }`
  - `buildSnapshot(input: { agents: Agent[]; work: Record<string, BackgroundWork>; summaries: Record<string, AgentSummary>; usage: Usage; now: number }): Snapshot`
  - `offlineSnapshot(now: number): Snapshot` → `message: "Escouade ne répond pas"`
  - `euros(n: number): string` → `2.41` → `"2,41 $"`

Règles que les tests figent :
- Statut : `waiting` si `agent.waiting` est vrai, sinon `agent.status`. Libellés : `waiting` « Attend ta réponse », `running` « En cours », `idle` « Attend », `error` « Planté », `done` « Fini ». Couleurs : `#f59e0b`, `#22c55e`, `#22c55e`, `#ef4444`, `#5b6472`.
- Ordre : waiting, running, idle, error, done ; ordre d'Escouade à statut égal. 30 agents au plus.
- `line` : « Attend ta réponse » si waiting ; sinon le premier paragraphe de `lastMessage`, 90 caractères au plus (« … » ajouté si coupé) ; `""` sans message. `last` : `lastMessage` à 280 caractères au plus.
- Sous-agents : seuls ceux `status === "running"` vont dans `subs` (8 au plus), `doing` à 80 caractères ; `subsDone` = ceux `done`.
- `totals.cost` = somme des `cost` des agents ; `costs` trié par coût décroissant, `share` = coût / coût max (0 à 1).
- Quotas : pour chaque compte `current`, un élément par `meter` ; `win` = `"5 h"` (300), `"7 j"` (10 080), `"mois"` (`null`), sinon `"<minutes> min"` ; `pct` arrondi ; `reset` = `"repart à HH:MM"` le jour même, sinon `"repart <jour de semaine>"` (fuseau local, `Intl.DateTimeFormat("fr-FR")`).

### Task 3: Client PhoneBox

**Files:**
- Create: `src/phonebox.ts`, `test/phonebox.test.ts`

**Interfaces:**
- Produces:
  - `type PhoneBoxConfig = { url: string; token?: string }` — `url` de `PHONEBOX_URL` (défaut `http://127.0.0.1:8765`), `token` de `PHONEBOX_TOKEN` (envoyé en `Authorization: Bearer` s'il existe).
  - `push(cfg: PhoneBoxConfig, key: string, value: unknown): Promise<void>` — `POST <url>/api/push/<key>`, JSON ; statut ≠ 2xx → `Error("PhoneBox a répondu <status>")`.
  - `type PermissionRequest = { request: string; type: "permission" | "plan" | "question"; agent: { id: string; name: string; project: string; projectId: string; ticket: string | null }; tool: string; arg?: string; input?: Record<string, unknown>; description: string | null }`
  - `toHookBody(r: PermissionRequest, cwd: string): object` → `{ hook_event_name: "PermissionRequest", session_id: r.agent.id, cwd, tool_name: r.tool === "ExitPlanMode" ? "ExitPlanMode" : r.tool, tool_input: { ...(r.input ?? {}), ...(r.arg && !r.input ? { command: r.arg } : {}), ...(r.description ? { description: r.description } : {}) } }` ; pour un `plan`, `tool_input.plan = r.arg`.
  - `askPermission(cfg: PhoneBoxConfig, body: object, signal: AbortSignal): Promise<"allow" | "deny" | null>` — `POST <url>/api/hooks/claude/permission` ; lit `hookSpecificOutput.decision.behavior` ; corps vide ou illisible → `null`.

  - `askPermission allow` : réponse `{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow"}}}` → `"allow"`.
  - `askPermission deny` : `behavior "deny"` + `message` → `"deny"`.

### Task 4: Le relais des approbations

**Files:**
- Create: `src/approvals.ts`, `test/approvals.test.ts`

**Interfaces:**
- Consumes: `PermissionRequest`, `toHookBody`, `askPermission` (Task 3) ; `callTool` (Task 1).
- Produces:
  - `type Deps = { ask: (body: object, signal: AbortSignal) => Promise<"allow" | "deny" | null>; answer: (request: string, decision: "allow" | "deny") => Promise<void>; cwdOf: (projectId: string) => string; log: (line: string) => void }`
  - `class ApprovalRelay { constructor(deps: Deps); sync(requests: PermissionRequest[]): void; inFlight(): string[] }`

Comportement : `sync` reçoit la liste entière de `list_requests`. Une demande `permission` ou `plan` jamais vue part (`ask`) ; les `question` sont ignorées. Une demande déjà vue n'est jamais renvoyée, même après `null`. Une demande en vol absente de la nouvelle liste est annulée (`AbortController.abort()`), sans `answer`. `allow`/`deny` → `answer(request, décision)` ; une erreur d'`answer` (déjà répondue dans Escouade) est journalisée et avalée. L'ensemble des ids vus est purgé des ids qui ne sont plus dans la liste (pas de fuite mémoire).

- [ ] **Step 1: Écrire les tests** avec des `Deps` factices (promesses contrôlées à la main) :
  - `forwards a new permission once` : deux `sync` de la même liste → `ask` appelé 1 fois.
  - `ignores questions` : `type "question"` → `ask` jamais appelé.
  - `answers allow` : `ask` résout `"allow"` → `answer("r1","allow")`.
  - `emptyBodyLeavesItAndNeverResends` : `ask` résout `null` → `answer` jamais appelé ; nouveau `sync` avec r1 → `ask` toujours 1 fois.
  - `abortsVanished` : r1 en vol, `sync([])` → le `signal` reçu par `ask` est `aborted`, `answer` jamais appelé, `inFlight()` vide.
  - `swallows answer errors` : `answer` rejette `"déjà répondue"` → pas d'exception non gérée, `log` appelé une fois.
- [ ] **Step 2: Lancer** → FAIL. **Step 3: Implémenter** `src/approvals.ts`. **Step 4: Lancer** → PASS.
- [ ] **Step 5: Commit** `git commit -m "feat: relais des permissions vers la carte de PhoneBox"`
